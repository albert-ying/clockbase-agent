# New data through the ClockBase CodingAgent and independent audit

For automatic human- or mouse-RNA refresh from a pinned local ARCHS4 release, or guarded
human-DNAm refresh from source-declared beta tables or paired EPIC IDATs and a pinned local reference,
use one configuration and your configured OpenAI credentials for model stages. Install the prerequisites
under [Install](#install) first:

```sh
bash run_pipeline.sh --refresh REFRESH_CONFIG.json --output REFRESH_ROOT
```

This command discovers GEO studies, checks first-public dates and operational
overlap, reconstructs literal source profiles, verifies local ARCHS4 membership,
extracts counts, runs the independent every-cell reader, generates provenance
wrappers, and calls the existing eight-stage pipeline and comprehensive audit.
It creates the intermediate plans itself. The source profile and independent
reader execute from hash-bound source snapshots. Model and scientific failures
remain in the complete discovery ledger; successful execution does not imply
scientific acceptance.

`REFRESH_CONFIG.json` uses this schema. Replace the source path/hash and select
the date window and limits before execution; the numbers below are configuration
examples, not measured performance or invoice costs. The original GEO corpus is
not needed for operational ingestion, but its absence keeps original-paper
temporal eligibility quarantined.

{

  "date_from": "2025-01-01",
  "date_to": "2025-12-31",
  "archs4": {"path": "/data/human_gene.h5", "sha256": "REPLACE_WITH_64_CHARACTER_SHA256"},

The comprehensive audit reviews source identity and design before it sees saved
outcomes. Its later review separately records molecular-input and clock evidence,
grouping and covariates, statistical method and estimates, and scientific claim
scope. Sixteen check judgments retain their citations and unresolved reasons;
conditional recalculation and a valid response contract do not make a result
scientifically accepted. The comprehensive adapter supports explicit OpenAI
`gpt-5.6-luna` and `gpt-6-luna`; unsupported comprehensive model settings stop
before discovery, producer work or budget reservations. The `comprehensive_audit` object declares that model,
tariffs and per-study call/cost caps; `pipeline` sets producer caps, and
`update_limits` sets the aggregate model budget. Resume with the same config and
output root: recorded requests and reservations remain charged to that budget.
Change `revision` for a changed source or policy, and retain the earlier run.
New runs can set `pipeline.service_tier` and `comprehensive_audit.service_tier`
to `"default"`; the producer CLI uses `--service-tier default`, and direct corpus
configurations use `api.service_tier`. The pipeline setting applies to both the
source assessor and producer. Each explicit setting is bound to the configuration
and request, and requires a returned `default` tier before content is used. A
missing or different returned tier retains the response, a typed diagnostic and
the full uncertain reservation, with no automatic retry. Omission preserves the
previous request and replay identity. The selected-stage top-level `service_tier`
policy marker alone does not add a transport option. Estimates still use the
declared tariffs and are not provider invoice totals.

The example opts into `source_label_pairs_v1`. It permits a source-design
proposal to declare an exact delimiter/token rule over a literal sample field,
with source evidence IDs and full case/control membership. The controller
checks that rule against every in-scope source row and records excluded rows;
it does not infer donor independence or accept a statistical conclusion from a
label. Omit `comprehensive_audit_policy` for the historical
`literal_fields_v1` behavior. The policy is fixed by the config and source-only
design replay, not by a model response.

Existing atlas users can add local `seen_worklist` and `seen_sample_sources`
declarations, each with `path` and `sha256`. The worklist must identify saved
analyses (`artifact_ids`) or explicit execution membership; a catalogue accession
alone is not evidence of prior analysis. Sample-family metadata enriches those
declared memberships. The refresh controller also records its own previous
pipeline attempts and completed analyses as separate membership categories.
It does not treat newly downloaded metadata as analyzed data.

Run the same command with `--until input` for a credential-free intake check;
then omit that option to advance the same source versions through the report.
`REFRESH_ROOT/refreshes/<config-id>/refresh-<stage>.json` links the phase receipts
and retains every enumerated GEO UID, including source exclusions, unavailable
assays, unsupported profiles, over-limit studies and unresolved executions.
The complete literal source profile remains intact when a hash-bound extraction
subset excludes an unavailable or over-limit study. The extraction subset never
changes a study's samples or biological groups.

For a fresh installation without a local RNA release, replace the `archs4`
declaration with the optional acquisition specification below. Keep
`max_release_bytes` and set it at least as high as `max_source_bytes`. The

download size, HDF5 dimensions and complete-file hash. Catalog timestamps select
a release and never establish a study's first-public date. The sealed selection
and immutable cache identity include the selected catalog's exact `id` and
opaque `checksum`. Its algorithm and hashed representation remain
`CANNOT VERIFY`; the catalog checksum is not presented as validation of the
downloaded file's SHA256. Source receipts retain only ETag, Content-Length,
Content-Type and Last-Modified response headers. Cookies and other session
headers are excluded.

These are explicit configuration examples, not an instruction to download or
measured resource use. The existing lifetime `network_budget` must cover both
the acquisition allocation and the discovery allocation. The example's maximum
transfer allocation includes room for catalog bytes; response bodies consume
that allocation, and uncertain transfers retain the request's full allowance.
The controller never raises a limit automatically. Model-call and dollar caps
continue to use the existing update registry.

For automatic DNAm reference bootstrap, set `source_acquisition.policy` to `geo_gse40279`, and omit both
`archs4` and `dnam_reference`. Its source/time/storage bounds must cover the GSE40279 download, and
`update_limits.max_input_bytes` must cover the reference plus study inputs. Source verification compares
the ordered table and scientific metadata with the producer's reference profile before downstream processing.

Acquisition and a pinned local source are mutually exclusive. Cache objects are
immutable and shared only through verified origin receipts. A new configuration
revision may check the current RNA catalog and reuse an unchanged completed
object. Repeating the identical configuration reads its sealed acquisition
receipt without catalog, HEAD or download requests. Both the refresh output and
cache have locks. The cache is separate from the output tree, must use persistent
storage, and enforces its total size and free-space reserve. A selected file must
fit before its payload request; room for source receipts is also retained.

Every acquisition reserves requests/bytes in the existing lifetime network
ledger and reserves its full time allocation in a separate immutable acquisition
control. Failed or interrupted attempts retain these reservations and any partial
objects; an unchanged resume cannot retry them. Partial objects require explicit
operator reconciliation. No transport retries, redirects or parallel download
connections are used by this mode. Successful source resolution is sealed before
the normal refresh version, discovery, extraction and audit stages execute.
The receipt is linked from the final refresh report. Existing local-source
configurations keep their prior behavior.

Unchanged completed phases resume without network or model calls. Failed or
interrupted phases remain terminal; they are not silently retried. New date
windows, sources or policies require a new explicit configuration revision.
The optional `candidate_offset` can bound a later discovery segment; all segments
share the same output's lifetime network and model reservations. Keep the same
`REFRESH_ROOT` to preserve those budgets. Network quotas are reserved before a
discovery run; model quotas are reserved by the existing update registry before
the corresponding child executes. Failed or uncertain usage is not automatically
refunded, and an existing output refuses changed lifetime limits. The report's
budget snapshot is cumulative at its creation time; the reservation ledgers
retain subsequent allocations. A new revision does not automatically retry
previously attempted studies or authorize changed scientific targets.

For guarded DNAm ingestion, change the modality to `human_dnam`, remove `archs4`
and `max_release_bytes`, and declare a local `dnam_reference` with exact `path`
and `sha256`. Source discovery uses the same query/date/overlap ledger. The
remaining network reservation checks one official GEO matrix listing per
eligible Series and accepts exactly one matrix. The Series and every Sample
must declare a human methylation array, one canonical platform, genomic DNA,
and exactly matching GSM membership. A nonempty matrix needs a literal source
beta-unit declaration and a separate numeric range check. An empty matrix needs
one source-declared beta-named text table or `.xlsx` workbook with an exact source-supported
sample crosswalk; the existing reconstruction and independent input verifier run
before the study enters the update registry. Source and decompressed input byte
limits apply. Missing references, ambiguous files and unsupported assays remain
per-study unresolved records. The same lifetime network reservation covers both
discovery and DNAm source resolution; a later revision does not retry a prior
sealed DNAm source attempt. No beta unit follows from `[0,1]` values alone, and
matching GSMs do not establish biological independence or clock applicability.
Mouse RNA uses the same bounded ARCHS4 refresh path when the plan declares
`mouse_rna` and pins the mouse release. The source profile, extraction batch,
independent every-cell readback and handoff must agree on mouse identity; a
human release or mixed organism declaration stops before downstream analysis.
The existing total-RNA source profile and mouse preprocessing/clocks remain in
force, with unsupported assays retained as unresolved records. Source
eligibility for the submitted-paper extension is separate. Software fixtures
check guarded routing, source identity and input recovery; empirical
performance and scientific acceptance require separate evidence.

VERSION --prior-audit VERSION/comprehensive-audit --budget ALLOWANCE.json --output
NEW_FOLLOWUP --revision REVISION --fresh-source-design`. The explicit option

New allowances accept exactly `gpt-5.6-luna` or `gpt-6-luna` with explicit
input/output tariffs and positive cost/call caps. This does not change the model
recorded in an earlier response or loosen the original-response checks.
The producer report, completed stages, prior failure, model receipts and budget
must verify before preparation and execution. Transport, policy, budget and
integrity failures are ineligible. Preparation makes no model calls; run the
frozen follow-up with `python -m audit_system.corpus_audit_2026_09_20
run-update-audit --output NEW_FOLLOWUP`. It reuses saved predictions, preserves
the old failed audit, and permits at most one completed-response contract retry
per source or review request. It does not infer biological units, merge empty
selectors, or accept scientific results automatically. Completed and unresolved
terminal resumes make no new model calls. Source narratives can contain published
findings; blinding excludes previous pipeline outcomes and judgments. The
default preparation remains the v1 replay of an already completed source design.

New update/refresh plans can explicitly set `pipeline.coding_completion_policy`
to `outputs_v1`. Before accepting a CodingAgent `<solution>`, this checks unchanged
source files, a host-recorded execution receipt and regular `aging_analysis.csv`
and `comparisons.json` files inside the workspace. It does not establish that the
source files were read or that the outputs are scientifically valid. The existing
output-schema and scientific validators still apply. A `CANNOT VERIFY` analysis
with the declared abstention outputs can complete this check.
Set `pipeline.coding_validation_retries` to `1` to allow one correction shared
across action-format and output-completion failures; setting it to `0` checks
completion without a correction. Feedback requests inspection and declared
outputs without choosing groups, tests or results. Transport, provider-policy,
budget and integrity failures do not create another correction, and changed
source files or execution receipts stop the run. The controller creates no
analysis output on the model's behalf. The producer CLI equivalents are
`--coding-completion-policy outputs_v1 --coding-validation-retries 1`.
The default remains `legacy`, and old frozen runs are not changed or retried.
The trace retains `format_validation` and adds `completion_validation` only
for the explicit completion policy.

## Install

Use Linux x86-64 with glibc 2.28 or later, Python 3.12 (the tested patch version was 3.12.9),
R, curl and bubblewrap. The Python environment is pinned in
`pipeline_requirements_2026_09_10.txt`, including CPU-only PyTorch required by
Biolearn. The captured matching R environment is R 4.5.1 with jsonlite 2.0.0, minfi 1.54.1,
illuminaio 0.50.0, IlluminaHumanMethylationEPICmanifest 0.3.0 and
IlluminaHumanMethylationEPICanno.ilm10b4.hg19 0.6.0. The
[session capture](src/dnam_idat_preprocess_2026_09_24.sessionInfo.txt) records the loaded packages and the
uncertainty about historical installation identity. Install these R dependencies before raw EPIC processing:

```bash
Rscript -e 'install.packages(c("BiocManager", "jsonlite"), repos="https://cloud.r-project.org"); BiocManager::install(version="3.21", ask=FALSE); BiocManager::install(c("minfi", "illuminaio", "IlluminaHumanMethylationEPICmanifest", "IlluminaHumanMethylationEPICanno.ilm10b4.hg19"), ask=FALSE)'
```

Package repositories can change; compare loaded versions with the capture before claiming a matching environment.
The optional `published_mouse_rle` profile also needs `edgeR`:

```bash
Rscript -e 'BiocManager::install("edgeR", ask=FALSE)'
Rscript -e 'stopifnot(requireNamespace("edgeR", quietly=TRUE))'
```

Git LFS is needed for a Git checkout. The code release contains materialized model assets, so an unpacked
release can run the setup script directly; initialize and pull LFS only in a Git checkout.

```bash
git lfs install --local
git lfs pull --include="pipeline_assets/**" --exclude=""
bash setup_pipeline_2026_09_10.sh
```

Set `OPENAI_API_KEY` securely in the shell or your secret manager. Do not put
the key in a command argument, source file or run directory. It is the only API
credential required. Installation, source downloads and model payloads remain
necessary; an API key does not supply molecular data or clock models.

## Run

The refresh schema above is the automatic intake route. For reader-supplied sources, use a
`clockbase-continuous-update-plan-v1` JSON plan with these fields:

| Field | Required contents |
|---|---|
| `schema` | `clockbase-continuous-update-plan-v1` |
| `limits` | Positive integers `max_studies`, `max_input_bytes`, `max_samples_per_study`, `max_child_seconds`; nonnegative `max_total_model_calls`, `max_total_cost_usd`; `concurrency: 1`; Boolean `allow_network` |
| `pipeline` | Producer/source-assessor model names, paired input/output tariffs, call/cost/output limits; supported options are defined in `src/update_pipeline_2026_09_20.py::PIPELINE_OPTIONS` |
| `comprehensive_audit` | `model` (`gpt-5.6-luna` or `gpt-6-luna`), positive `max_calls`, `max_cost_usd`, `input_usd_per_million`, `output_usd_per_million`; optional `service_tier: "default"` |
| `studies` | Study objects with `study_id`, `modality` (`human_rna`, `mouse_rna`, `human_dnam`), optional `target` and `analysis_revision`, and `sources` |
| `sources` in each study | `series` and `samples`, plus exactly one of `matrix` or `archs4`; DNAm preprocessing also needs `dnam_reference` |
| Each source declaration | Exactly one `path` or public HTTPS `url`; local paths require a lowercase SHA256, and optional `max_bytes` bounds that source. Relative paths resolve from the command's working directory. |
| Optional `discovery` | Hash-bound candidate manifest with schema `clockbase-update-candidates-v1` and a `studies` list; merged with explicit studies |

All sources must exist or be acquired under the declared network policy. The repository supplies code and model
assets; the bundle supplies the verifier rebuild inputs, not arbitrary new-study molecular sources. A changed
study version in an existing registry also requires the preceding `supersedes_version` identity.
Run from the release root:

```bash
bash run_pipeline.sh --plan UPDATE_PLAN.json --output UPDATE_REGISTRY --until report
```

The default `report` stage includes the comprehensive audit. An earlier `--until`
value is a partial run. `AUDIT_EXECUTION_COMPLETED` records completed execution;
scientific acceptance remains a separate outcome. Changed inputs require a new
version, and failed versions are retained without automatic paid retries.

For the earlier eight-stage producer only, including its narrower numerical
audit, use the explicit mode below. It does not execute the sixteen-check audit:

```bash
PYTHON=.venv-pipeline/bin/python bash run_pipeline.sh --producer-only \
  --study GSE149866 --modality mouse_rna \
  --target 'Glucosylceramide synthase inhibition in BBS mutant adipose versus untreated BBS mutant adipose at the same age' \
  --output .clockbase-runs/GSE149866-example \
  --max-cost-usd 2 --max-calls 8 --max-output-tokens 3500
```

The example is development-exposed, not a held-out case. For a new study change
the accession, modality and scientific comparison. With no local source given,
RNA acquisition selects and ETag-pins the current official ARCHS4 gene file for
that species. It downloads tens of GB once into `.clockbase-cache`, then extracts
the study with exact GSM membership. Sufficient persistent disk space is required.
Use `--archs4 /path/to/species.h5` to reuse a release, or `--matrix counts.csv.gz`
for a gene-by-GSM matrix of raw Ensembl counts. Counts must precede normalization.

For human methylation use `--modality human_dnam`. The adapter obtains the unique
GEO Series Matrix or accepts `--matrix beta.csv.gz` (probe-by-GSM, beta values in
[0,1]). Ambiguous platforms and absent processed beta values stop with a recorded
dependency. The explicit EPIC IDAT route below can supply a source-bound beta
matrix for supported raw inputs. The adapter acquires/caches the GSE40279 reference used
by the inspected producer; `--dnam-reference` can point to its existing Series
Matrix. It never invents a reference vector or runs clocks on empty matrices.

For an empty matrix with a locally available, GEO-linked supplementary beta
table, add `--dnam-supplement /path/to/GSE..._beta.txt.gz`. The input stage
reconstructs GSM columns from explicit IDs or exact source metadata tokens,
preserves all uniquely identified assay features (including non-`cg` rows),
and independently compares every row and value. It rejects ambiguous or
incomplete sample mappings. A source-declared `.xlsx` supplement is also supported
when it contains one worksheet with explicit text sample and feature identifiers.
Worksheet XML tokens are reconstructed, then an independent openpyxl reader
compares every cell. Merged ranges, formulas, boolean, error and date cells stop the conversion;
worksheet dimensions cannot substitute for observed row counts. Condition means
and detection P values cannot be assigned to individual samples. Multiple sheets
require an explicit future selection rule. Originals and failed attempts remain preserved.
PASS at this stage verifies input reconstruction only; biological units,
clock applicability and scientific results still require their own checks.
This producer-only option consumes a local supplement. The canonical `--refresh`
route can discover and download supported source-declared beta supplements under
its explicit network budget. Other raw platforms require a declared processing
adapter; the EPIC route below does not authorize an unrecorded preprocessing choice.
Use `--until input` to complete this stage before any model call.

imputation. Single-array and joint outputs are compared as repeatability of the

`pipeline.source_contract_policy: "literal_field_refs_v1"` in an update plan,

every inserted string and the packet, transport and implementation hashes.

apply. This policy also retains the existing conservative downgrade of advisory
PASS domains that explicitly contain unresolved evidence. It never approves a
scientific result. The default remains `strict`; old failed executions require
an explicit new version, and archived evaluations are unchanged.

## Resume, models and cost

Repeat the same command to resume. Configuration, implementation, source and
completed output hashes must agree. Changed inputs need a new output directory;
completed outputs are never silently overwritten. Requests have persistent
reservations before transport. A timeout with uncertain billing is not retried
automatically. A verified stored response can be reused for the identical request.

`--until metadata|input|design|preprocess|clocks|agent|audit|report` stops after a stage;
omitting it runs through the report. Partial execution is never reported as a
complete pipeline. Failed attempts and original agent outputs remain in the run.
Only one process may own a run directory.

Choose models and paired role-specific tariffs in the plan before a new execution. The update controller
supports the comprehensive-audit models named in the schema above. The producer-only runner uses OpenAI directly,
reads `OPENAI_API_KEY`, and has no automatic provider/model fallback. `run_pipeline.sh` prefers `.venv-pipeline`;
set `PYTHON` to override it. Cost reservations are configured estimates, not invoices.

## Outputs and scientific limits

Open `08_report/attempt-*/report.html`. The run also contains source URLs/dates,
GSM membership, input hashes, preprocessing parameters, clock coefficients or
model hashes, agent code and execution receipts, model usage, original analyses,
source-only design proposals, detected disagreements and candidate repairs.

The numerical repair adapter supports independent two-group Welch comparisons
with sufficient source support. Paired/repeated/confounded designs are retained
as unresolved rather than coerced into Welch. Repairs are recomputed from fresh
clock outputs and checked by a separate formula. Conditional per-run BY
adjustment includes unsuccessful endpoints in the declared comparison-by-clock
family. Undefined requests leave its complete denominator unknown and withhold
adjusted P values. This is not the paper's corpus-wide FDR.
This entry point does not silently restore the blocked historical score-merging
path or update ClockBase composite rankings and publication figures.

The audit also checks existing unadjusted Student calculations without changing
them to Welch merely because another agent proposed Welch. A disagreement in
grouping is a request for source adjudication, not confirmed ground truth.
Each audit saves `decision-ledger.jsonl` and `decisions.json`; calculation PASS
is conditional on declared samples and assumptions and does not authorize an
aging claim. `source-verification.json` records source bindings, failures and
unknowns. `final-outputs.json` separates selected outputs from immutable original
analyses and repair proposals. `repair_decision` records whether a proposed
repair was accepted, rejected or unresolved. `study_decision_status` is PASS
when at least one comparison is accepted; aggregate `scientific_status` can
still be FAIL or CANNOT VERIFY for other clocks. `--recheck-audits` in `audit_system.report_2026_09_10` can re-audit
archived predictions and analyses into a new directory without spending on models.

To verify the complete-measurement profiles from a GEO series matrix and its
source metadata, use a new output directory:

```bash
.venv-pipeline/bin/python -m audit_system.report_2026_09_10 \
  --check-measurement-profiles --evidence PATH_TO_SERIES_MATRIX.txt.gz \
  --source-metadata PATH_TO_SOURCE_METADATA.csv --output NEW_MEASUREMENT_RUN
```

This mode streams the matrix, retains every source sample, records missing
measurements and performs no imputation. It makes no model API calls. Its
table and receipts describe clock execution and profile decisions, without
creating an intervention contrast or an audit error-rate estimate.

This pipeline has no held-out benchmark, independent reference adjudication or frozen family membership.
